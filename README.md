# NBolzoo

Монголын болзооны санааны платформ. Улаанбаатарын 365 санаа, 21 аймгийн онцлох газар,
урилга үүсгэгч, хосын тоглоом, нийгэмлэг, үйлчилгээний жагсаалт — бүгд нэг дор.

**Амьд хувилбар:** https://nbolzoo.vercel.app

## Технологи

- **Frontend:** vanilla HTML / CSS / JavaScript. **Build step байхгүй** — файлыг шууд serve хийнэ.
- **Backend:** Firebase (Authentication, Cloud Firestore, Cloud Storage) — compat SDK-г CDN-ээс ачаална.
- **Hosting:** Vercel, `main` салбараас автомат deploy.
- **PWA:** manifest + pass-through service worker (cache хийдэггүй — доор тайлбарласан).

> **Яагаад build step байхгүй вэ?** Төсөл нь олон бие даасан HTML хуудаснаас бүрдэх бөгөөд
> контент нь статик JS файлд байдаг. Bundler нэмэх нь хөгжүүлэлтийн хурдыг сайжруулахгүйгээр
> нарийн төвөгтэй байдал нэмнэ. Файлыг засаад refresh дарахад л шууд харагдана.

## Эхлүүлэх

Build хийх шаардлагагүй. Статик сервер хангалттай:

```bash
git clone https://github.com/bayraaaBMG/Nbolzoo.git
cd Nbolzoo

# Аль нэгийг сонгоно
python -m http.server 8000
npx serve .
```

Дараа нь `http://localhost:8000` руу орно.

> `file://` протоколоор нээвэл Firebase Auth болон service worker ажиллахгүй —
> заавал HTTP сервер ашиглана.

## Firebase тохиргоо

Тохиргоо нь [`js/firebase-init.js`](js/firebase-init.js) дотор байна. Firebase-ийн
client `apiKey` нь **нууц биш** — энэ нь зөвхөн төслийг таних зориулалттай бөгөөд
бодит хамгаалалт нь бүхэлдээ security rules дээр байдаг ([Firebase-ийн албан ёсны
тайлбар](https://firebase.google.com/docs/projects/api-keys)).

### Дүрмийг deploy хийх

**Шинэ collection нэмсэн эсвэл дүрэм өөрчилсөн бол ЗААВАЛ deploy хийнэ.** Эс бөгөөс
шинэ боломж production дээр `permission-denied` алдаа өгнө:

```bash
npm install -g firebase-tools
firebase login
firebase deploy --only firestore:rules,storage:rules
```

### Firestore индекс

Composite индексийг зориудаар аль болох бага ашигласан — оронд нь цөөн тооны баримтыг
татаад client дээр эрэмбэлдэг (banners, reports, services). Шаардлагатай индексүүд
[`firestore.indexes.json`](firestore.indexes.json) дотор.

## Эрхийн систем

Гурван түвшин. Түвшин нь `admins/{uid}` баримтын `role` талбарт хадгалагдана.

| Эрх | Owner | Admin | Moderator |
|---|:---:|:---:|:---:|
| Самбар нээх | ✅ | ✅ | ✅ |
| Пост/сэтгэгдэл **нуух** | ✅ | ✅ | ✅ |
| Гомдол шийдвэрлэх | ✅ | ✅ | ✅ |
| Пост/сэтгэгдэл **устгах** | ✅ | ✅ | ❌ |
| Хэрэглэгч хориглох | ✅ | ✅ | ❌ |
| Контент засах / нуух / дараалал | ✅ | ✅ | ❌ |
| Banner удирдах | ✅ | ✅ | ❌ |
| Үйлчилгээ хянах | ✅ | ✅ | ❌ |
| Өнгө / цэс / нүүр тохируулах | ✅ | ✅ | ❌ |
| **Moderator** эрх олгох | ✅ | ✅ | ❌ |
| **Admin** эрх олгох | ✅ | ❌ | ❌ |
| Хэрэглэгч устгах | ✅ | ❌ | ❌ |

**Owner-ийн тухай.** Ганц үндсэн эзний account нь [`js/auth.js`](js/auth.js)-ийн
`OWNER_EMAIL` болон [`firestore.rules`](firestore.rules)-ийн `isOwnerEmail()` дээр
хатуу бичигдсэн. Эхний удаа нэвтрэхэд `admins/{uid}` баримт нь өөрөө үүснэ. Үүний
дараа бүх шалгалт UID-д тулгуурлана. **Owner эрхийг хэн ч — өөрөө ч — хасах, эсвэл
owner account-ыг хориглох боломжгүй.** Энэ нь lockout-оос хамгаална.

> Энэ хоёр газрыг **үргэлж хамт** өөрчилнө. `rules_test.js` нь зөрүүтэй болсон эсэхийг шалгадаг.

**Хамгийн чухал зарчим:** [`js/roles.js`](js/roles.js) нь зөвхөн **UI**-г зөв харуулахад
зориулагдсан. Хэрэглэгч frontend-ийг чөлөөтэй өөрчилж чадна. Бодит хамгаалалт нь
**бүхэлдээ** `firestore.rules` / `storage.rules` дээр байна. Шинэ эрх нэмэх бүрдээ
**хоёуланд нь** хэрэгжүүлнэ.

## Контентын загвар (overlay CMS)

Редакцийн контент (365 УБ санаа, 21 аймаг, 247 бэлэг) нь **JS файл дотор эх сурвалж
хэвээр** байна. Firestore нь зөвхөн **давхарласан өөрчлөлтийг** хадгална:

```js
contentOverrides/{ub|aimags|gifts} = {
  hidden: [id, ...],           // нуусан
  order:  [id, ...],           // жагсаалтын эхэнд гаргасан
  edits:  { id: {...} },       // талбар дарж бичсэн
  added:  [ {id, ...} ],       // admin-аас нэмсэн шинэ зүйл
}
```

**Яагаад ингэсэн бэ?**

| | Бүх контентыг Firestore руу нүүлгэвэл | Overlay |
|---|---|---|
| Хуудсын уншилт | 500+ баримт | 1 баримт |
| Эхний render | Async — SEO/LCP муудна | Шууд, одоогийнхтой ижил |
| Баталгаажсан dataset | Эрсдэлд орно | Хөндөгдөхгүй |
| Буцаах | Backup-аас сэргээх | Override устгахад анхны байдал эргэнэ |

Урсгал: хуудас эх өгөгдлөөрөө **шууд** зурагдана → override ирэхэд **дахин** зурагдана.
Firestore унтарсан ч хуудас бүрэн ажиллана (*fail-open*).

> ⚠️ **Анхаарах:** `gifts` нь `id`-гүй байсан тул ачаалах үед индексээр дугаарлагддаг
> ([`js/gifts.js`](js/gifts.js)). Массивын **дунд** шинэ бэлэг оруулбал өмнө нь хийсэн
> нуулт/засвар өөр бэлэг рүү шилжинэ — зөвхөн **ард** нь нэмнэ.

## Хамгаалалт

**Дүрмийн давхарга.** Бүх эрх `firestore.rules` / `storage.rules` дээр хэрэгждэг.
Frontend дээрх шалгалт нь зөвхөн UI-д зориулагдсан.

**XSS.** Хэрэглэгчийн оруулсан бүх текст render хийхээсээ өмнө `escapeHtml()`
([`js/core.js`](js/core.js)) -ээр дамжина. Энэ нь `<`, `>`, `&` -ээс гадна `"` болон
`'` -г мөн escape хийдэг тул attribute дотор ч аюулгүй. Regression тест нь шинэ render
зам бүрийг сканнердаж, escape хийгээгүй талбар байвал алдаа өгнө.

**URL хамгаалалт.** Бизнесийн `website` талбар нь `http://` эсвэл `https://` -ээр
эхлэхийг шаарддаг — `javascript:` зэрэг схемийг эх үүсвэр дээр нь таслана.

**Өөрийгөө зөвшөөрөх боломжгүй.** Үйлчилгээ бүртгүүлэхэд `status` нь заавал `pending`
байх ёстой, эзэн нь өөрийн `status`-аа өөрчилж чадахгүй — хоёулаа дүрмээр албадсан.

**Хориглосон хэрэглэгч.** `isBanned()` нь rules дээр шалгагддаг тул түдгэлзүүлсэн
хэрэглэгч Firestore руу шууд хандаж ч пост бичиж чадахгүй.

**Нууцлал.** `bannerEvents` нь зөвхөн `bannerId` болон `type` -г хадгална. Хэрэглэгчийн
ID, IP, хөтчийн ул мөр бүртгэдэггүй.

## Тест

Browser автоматжуулалт (Playwright г.м.) энэ орчинд байхгүй тул тестүүд нь Node-ийн
`vm` модулийг ашиглан хуудсын script гинжийг **браузер шиг нэг lexical scope дээр**
ажиллуулж шалгадаг.

```bash
node tests/run-all.js          # бүгдийг нэг дор (syntax + 8 багц)
```

Тус тусад нь:

```bash
node tests/page_load.js .      # 12 хуудас бүрэн ачаалагдах эсэх
node tests/roles_test.js       # эрхийн матриц (44 шалгалт)
node tests/rules_test.js       # security rules статик шалгалт (36)
node tests/cms_test.js         # overlay логик (18)
node tests/cms_integration.js  # бодит dataset дээр (18)
node tests/xss_test.js         # XSS regression (16)
node tests/link_check.js       # холбоос / холболт (22)
node tests/data_check.js       # dataset бүрэн бүтэн байдал (11)
```

**Юуг шалгадаггүй вэ (шударга байх үүднээс):**

- Security rules-ийг **Firebase emulator дээр ажиллуулаагүй**. `rules_test.js` нь зөвхөн
  статик шалгалт — дүрэм бодитоор татгалзаж байгааг баталгаажуулдаггүй.
- Дэлгэцийн хэмжээ (320–1920px) дээрх **харагдацыг нүдээр шалгаагүй** — browser байхгүй.
- Хэрэглэгчийн бодит урсгалыг (нэвтрэх → бүртгүүлэх → зөвшөөрөх) **гараар тестлээгүй**.

## Deploy

`main` салбар руу push хийхэд Vercel автоматаар deploy хийнэ.

**Security rules нь Vercel-ээр deploy хийгддэггүй.** Дүрэм өөрчилсөн бол тусад нь:

```bash
firebase deploy --only firestore:rules,storage:rules
```

### Service worker

[`service-worker.js`](service-worker.js) нь **зориудаар cache хийдэггүй** — бүх хүсэлт
шууд сүлжээгээр явна. Сайт нь Firestore-ийн бодит цагийн өгөгдөл дээр тулгуурладаг тул
хуучирсан хувилбар харагдах эрсдэлийг бүрэн арилгасан. Түүний цорын ганц зорилго нь
PWA "суулгах боломжтой" шаардлагыг хангах.

## Хөгжүүлэлтийн зарчим

Энэ төсөл дараах дүрмүүдийг чанд баримталдаг:

1. **Зохиомол өгөгдөл байхгүй.** Хуурамч статистик, үнэлгээ, сэтгэгдэл, бизнес,
   нийгмийн сүлжээний холбоос үүсгэхгүй. Тоо бүр бодит эх сурвалжаас гарна.
2. **Тоог hardcode хийхгүй.** "531 санаа" гэх мэт тоог HTML дотор бичихгүй — dataset-ээс
   автоматаар тооцоолно. Ингэснээр контент өөрчлөгдөхөд тоо хэзээ ч хуучирахгүй.
3. **Баталгаажаагүй контентыг харуулахгүй.** Аймгийн онцлох газар бүр эх сурвалжтай
   (`source`, `verifiedAt`). Баталгаажуулж чадахгүй бол **устгана** — тодорхойгүй
   мэдээллийг үлдээхгүй. Байршил эргэлзээтэй бол газрын зургийг нуудаг.
4. **Fail-open харагдац, fail-closed хамгаалалт.** Тохиргоо/CMS ачаалагдахгүй бол хуудас
   анхны байдлаараа ажиллана. Харин эрхийн шалгалт эргэлзээтэй бол татгалзана.
5. **Хоёр давхаргат эрх.** UI дээрх шалгалт бүрд rules дээрх хос шалгалт байх ёстой.
